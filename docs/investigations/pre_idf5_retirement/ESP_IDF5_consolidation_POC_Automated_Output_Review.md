## Retained comments requiring later human review

The transformer deliberately preserved comments in retained source. Review of
the generated output identified the following comments or adjacent whitespace
that may no longer be appropriate after consolidation:

- `targets/esp32/esp32_neopixel.c` retains the heading `IDF version-specific
  includes`, although only the selected IDF5 includes remain.
- `targets/esp32/esp32_neopixel.c` retains an orphaned `Legacy data (IDF < 5
  only)` heading after the complete legacy data block was removed.
- `targets/esp32/rtosutil.c` still describes compatibility with IDF3, IDF4 and
  IDF5 in its file header and timer-macro heading.
- `libs/network/esp32/jswrap_esp32_network.c` retains an `IDF 4/5` description
  beside code now retained solely as the POC's IDF5 backend.
- `targets/esp32/jshardwarePulse.h` says that an IDF5 handle is stored as
  `void *` "for compatibility"; the intended remaining compatibility should be
  confirmed before changing that wording or type.
- Removal of large legacy blocks in `targets/esp32/esp32_neopixel.c` leaves
  some additional vertical whitespace. The automated pass preserved retained
  source spacing except for the specifically required end-of-file correction.

These are review findings, not automated transformation failures. They have
not been edited into the generated source. If a correction is accepted, it
must be made only after the automated-output commit and recorded separately in
accordance with Sections 4.8 and 7.5 of the specification.
